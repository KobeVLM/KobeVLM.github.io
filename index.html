IT344 · SAM Topic 06

DHCP & DNS Servers

DHCP — Dynamic Host Configuration Protocol

A network management protocol that automatically assigns IP addresses and other network parameters to devices. Operates at the Network layer of TCP/IP.
DHCP Server
Centrally installed on the network. Manages the pool of IP addresses and assigns them to clients on request.
DHCP Client
Every device on the network runs a DHCP client that requests IP configuration automatically when it connects.

The DORA Process Key Concept

Client  →  Server   DISCOVER   "Is there a DHCP server? I need an IP."
Server  →  Client   OFFER      "Here, take 192.168.1.15 for 8 hours."
Client  →  Server   REQUEST    "Yes, I'll take 192.168.1.15."
Server  →  Client   ACK        "Confirmed. It's yours until [lease expiry]."
✅ Pros
  • Centralized IP management
  • Automated TCP/IP configuration
  • Easy to add new devices
  • Reuses IP addresses efficiently
  • Ideal for wireless / mobile users
❌ Cons
  • IP conflicts can occur
  • Clients accept any DHCP server (rogue server risk)
  • No network access if DHCP server is down
  • Hostname doesn't change with new IP

DHCP supports both IPv4 and IPv6 (the IPv6 version is called DHCPv6). It was first defined in October 1993 and is based on BOOTP (Bootstrap Protocol).

DNS — Domain Name System

DNS acts as the internet's phonebook. It translates human-readable domain names (e.g., google.com) into IP addresses that computers use to communicate.

The 4 Types of DNS Servers

#Server TypeRole
1Recursive ResolverReceives queries from clients (built into your OS). Contacts other DNS servers to find the answer.
2Root NameserverFirst step. Doesn't know the IP but knows who handles .com, .net, .ph, etc.
3TLD NameserverHandles top-level domains (.com, .net). Points to the authoritative nameserver for the domain.
4Authoritative NameserverThe final answer. Contains the actual DNS record with the IP address.

DNS Query Flow (No Cache)

Browser asks: "What is the IP for google.com?"
  → Recursive Resolver → Root Nameserver → "Ask .com TLD server"
  → TLD Nameserver → "Ask google.com's authoritative server"
  → Authoritative Nameserver → "It's 142.250.x.x"
  → Resolver returns IP to browser → Browser connects to 142.250.x.x
Exam tip: DNS is distributed and fault-tolerant by design. Administrators can delegate authority over subdomains to other name servers — avoiding a single central database that could fail.

Practice Questions

Q: What layer of the TCP/IP model does DHCP operate on?
The Network (Application) layer of the TCP/IP model. DHCP uses UDP, ports 67 (server) and 68 (client).
Q: A client PC just joined a network and has no IP. What is the very first message it sends?
A DHCPDISCOVER broadcast. It's broadcast because the client doesn't yet know the server's address. (DORA: Discover → Offer → Request → Acknowledge)
Q: What is the difference between a Root Nameserver and an Authoritative Nameserver?
A Root Nameserver is the starting point of DNS resolution; it knows where the TLD servers are but not the final IP. An Authoritative Nameserver holds the actual DNS record and provides the definitive IP address for a domain.
IT344 · SAM Topic 07

File and Share Permissions

Two Types of Windows Permissions

NTFS Permissions
  • File system level control
  • Applied on NTFS-formatted volumes
  • Applies to local AND network users
  • Very granular permission levels

Levels: Full Control · Modify · Read & Execute · List Folder · Read · Write
Share Permissions
  • Network-level control only
  • Applied when folder is shared over network
  • Applies ONLY to network users
  • Less granular

Levels: Full Control · Change · Read

Comparison Table

The Most Restrictive Rule: When NTFS and Share permissions are both set, Windows uses whichever is more restrictive. The combined effective permission is the intersection of both permission sets.

Explicit vs. Inherited Permissions

Explicit Permissions
Directly assigned to a specific file or folder.

✓ Always takes priority over inherited
Use when: a sub-folder needs different access than its parent, or a specific user needs unique rights.
Inherited Permissions
Automatically passed down from a parent folder to its children.

Default behavior in Windows.
Can be disabled via the Disable Inheritance button in Advanced Security Settings.

Sharing Methods

🔗 Mapped Drive (Persistent)
A shared folder is mapped to a drive letter (e.g., Z:) on the user's computer. Reconnects automatically on login. 
net use Z: \\Server\SharedFolder /persistent:yes
📁 UNC Path (Direct Access)
Access shared folders directly via Universal Naming Convention path. Open Run (Win+R): 
\\computername\sharedfolder

Practice Questions

Q: A user has Share permission = Full Control, but NTFS permission = Read. What can they actually do?
They can only Read. The most restrictive rule applies: the effective permission is the intersection of NTFS and Share — the more restrictive Read wins over Full Control.
Q: A local user (not accessing via network) has NTFS = Modify but there's a Share = Read permission. What happens?
The local user gets Modify. Share permissions only apply to network users. Since the user is local, Share permissions are irrelevant and only NTFS applies.
Q: What is the difference between Explicit and Inherited permissions? Which takes priority?
Explicit permissions are directly set on the specific file/folder. Inherited permissions flow down from the parent folder. Explicit permissions always take priority over inherited ones. You can break inheritance via "Disable Inheritance" in Advanced Settings.

Essential Commands

# View permissions
ls -l

# Change permissions (octal)
chmod 755 filename      # owner=rwx, group=r-x, other=r-x
chmod 644 filename      # owner=rw-, group=r--, other=r--
chmod 400 filename      # owner=r-- only (read-only, secure)

# Change permissions (symbolic)
chmod u+x filename      # add execute for user/owner
chmod g-w filename      # remove write for group
chmod o=r filename      # set other to read-only
chmod a+r filename      # add read for all (a = all)

# Change ownership
chown username filename
chown username:groupname filename
chown -R username /folder   # recursive

# Change group
chgrp groupname filename

Activity 7 — Secure Root SSH Access
Disabling direct root SSH login (security best practice): 
# Edit SSH config
sudo nano /etc/ssh/sshd_config

# Find and change this line:
PermitRootLogin yes   # ← INSECURE
PermitRootLogin no    # ← SECURE

# Restart SSH service to apply
sudo systemctl restart sshd

# To become root after SSH as normal user:
sudo su -
# or
sudo -i
⚠️ Before disabling root SSH, ensure you have a sudo user that can escalate! Otherwise you'll lock yourself out.
Activity 8 — Data Backup for Developer
Creating backups using tar and cron: 
# Create a compressed archive backup
tar -czvf backup_$(date +%Y%m%d).tar.gz /path/to/data

# Flags: c=create, z=gzip compress, v=verbose, f=filename

# Extract a backup
tar -xzvf backup_20260419.tar.gz

# Schedule automatic backup via cron
crontab -e
# Add this line for daily backup at 2AM:
0 2 * * * tar -czvf /backup/dev_$(date +\%Y\%m\%d).tar.gz /home/dev/

# Verify cron jobs
crontab -l

IT344 · Assignment Answers

Assignment: NTFS & Share Permissions

1a. Compare & Contrast: What is the difference between NTFS and Windows sharing permissions?

NTFS Permissions are enforced at the file system level and apply to every user — both local users and network users. They offer very granular control with levels like Full Control, Modify, Read & Execute, List Folder Contents, Read, and Write. NTFS permissions persist whether a user is sitting at the machine or accessing it over the network.

Share Permissions are a network-level control and only apply when a user accesses a folder through a network share. They have only three levels — Full Control, Change, and Read — and have no effect on users logged in locally to the machine. Share permissions act as the first gate for network access, while NTFS permissions enforce the final boundary.

FeatureNTFSShare
Who it applies toLocal + Network usersNetwork users only
Where enforcedFile system (disk level)Network share point
Granularity6+ levels3 levels
Works offline (local)YesNo
1b. Give at least one example scenario where the combination of both affects user access.
Scenario: An admin shares a folder "Reports" over the network. The Share permission is set to Full Control for "Everyone," but the NTFS permission for a specific user, Alice, is set to Read only.

Result: Even though the Share permission grants Alice Full Control, the NTFS permission (Read) is more restrictive. Windows applies the most restrictive rule, so Alice can only read the files — she cannot modify, delete, or create new files in that folder. The Share permission "promise" is effectively overridden by NTFS at the file system level.

2a. Critical Thinking: Why does Windows apply the "most restrictive" rule when combining NTFS and sharing permissions?

Windows applies the most restrictive rule because it follows a security-first, least-privilege principle. The intent is that if any layer of permission restricts access, that restriction should hold. This prevents a scenario where a misconfigured Share permission accidentally grants more access than the administrator intended at the file system level, or vice versa.

Think of it as two security guards at two doors. Even if one guard lets you through, the other can still stop you. The most restrictive guard always wins — ensuring no single configuration mistake opens a dangerous loophole.

2b. How does this protect files in a multi-user environment?

In a multi-user environment (e.g., a school lab or office), different users may belong to different groups with different privilege levels. The most-restrictive rule ensures:

  • No accidental privilege escalation — a wide-open Share permission can't bypass a tight NTFS restriction.
  • Defense in depth — even if an attacker compromises the network share settings, NTFS permissions provide a second barrier.
  • Granular user control — admins can confidently set Share to "Full Control for Everyone" for simplicity, and use NTFS to fine-tune what each user/group can actually do per file or folder.
3. Application: You're setting up a shared folder for classmates who should view files but NOT delete them. What permissions do you assign? Justify.
Share Permission Setting
Set to: Read

This allows classmates to access the shared folder over the network and see its contents, but the "Change" and "Full Control" options that would allow deletion are not granted at the share level.
NTFS Permission Setting
Set to: Read & Execute (or just Read)

This allows opening and reading files. Crucially, do NOT grant Write or Modify, which would enable file modification or deletion.
Justification: By setting both Share and NTFS to Read-level, you ensure classmates can open and view any file in the folder but cannot delete, rename, or modify them. The most-restrictive rule reinforces this — even if one layer is accidentally changed, the other acts as a safety net. NTFS "Read" specifically excludes the Delete special permission, which requires "Modify" or higher.
What to avoid: Do not grant "Change" on Share or "Modify/Full Control" on NTFS — both include delete capability. Also avoid granting "Write" which allows creating/overwriting files.

Key Definitions to Remember

EET vs LET
EET (Earliest Event Time) = the earliest a node can be reached.
LET (Latest Event Time) = the latest a node can be reached without delaying the project.

For the start node: EET = LET = 0
For the end node: EET = LET = project duration
Float Types
Total Float = LF − EF = LS − ES (how much an activity can be delayed without delaying the project)

Free Float = EET(successor) − EF (how much without delaying any successor)

Critical activities: TF = 0
