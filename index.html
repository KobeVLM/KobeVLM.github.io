Certificate Repository

True or False: A certificate repository stores revoked certificates only.
❌ You answered: TRUE (HI)
✅ Correct: FALSE (LO)
A certificate repository is a publicly accessible centralized directory of ALL digital certificates — used to view certificate status. The CRL (Certificate Revocation List) stores only revoked certs. These are NOT the same thing.

RA vs CA vs Intermediate CA

Which most accurately describes the role of an RA, CA, or intermediate CA?
❌ You answered: "The intermediate CA performs functions on behalf of a CA."
✅ Correct: "An RA performs functions on behalf of a CA."
RA (Registration Authority) = handles the administrative tasks FOR the CA (identity verification, collecting cert requests). It performs functions on behalf of the CA.

Intermediate CA = sits between the Root CA and end-users to issue certificates. It does NOT perform functions "on behalf of" — it issues its own certs under the root's authority.

Memory trick: RA = Reception Area (processes requests for the boss/CA). Intermediate CA = Middle Manager (has its own authority, delegated by the root).

CSR Generation Process

Which most accurately describes the CSR generation process?
❌ You likely confused which key is sent / used to sign
✅ Correct: Create keys → sign request with private key → send public key to RA → CA issues certificate
Step 1: Generate a key pair (public + private)
Step 2: Sign the CSR with your PRIVATE key (proves you own it)
Step 3: Send the PUBLIC key + signed request to the RA/CA
Step 4: CA verifies and issues the digital certificate

🔑 NEVER send the private key to anyone — EVER. If an option says "send private key to RA," it is ALWAYS wrong.

Certificate Suspension vs. Revocation

An employee's leave has been extended by 9 months. What should the company do to their digital certificate?
❌ You answered: Revoke it
✅ Correct: Suspend it (listed as "Annul it" trap — answer is actually suspend/hold)
Revoke = permanent cancellation. Used for: compromise, employee termination, fraud.
Suspend = temporary hold. Used for: extended leave, investigation, temporary role change.

Since the employee is expected to return (just longer leave), the cert should be suspended, not revoked. Revoking would require issuing a brand new cert later.

Cryptoperiod

This characteristic refers to the length of time a key is authorized for use.
❌ You answered: Duration
✅ Correct: Cryptoperiod
"Duration" sounds right but is NOT the technical term. The correct term is Cryptoperiod. It defines the active lifespan of a cryptographic key. After the cryptoperiod ends, the key must be replaced even if it hasn't been compromised.

Application Allow List

OS-level protection where only approved applications can run; unapproved items won't function.
❌ You answered: Antivirus
✅ Correct: Application Allow List
Antivirus = detects and removes known malware signatures
Application Allow List = proactive prevention — only whitelisted apps can execute. Unapproved programs simply cannot run.

This is an OS-level control, not AV software.

Web of Trust

This CA model is based on direct trust, where each user signs a digital certificate then exchanges with all other users.
❌ You answered: Certificate of Trust
✅ Correct: Web of Trust
Web of Trust = decentralized model. No central CA. Users sign each other's public keys. Used in PGP/GPG email encryption. If Alice trusts Bob, and Bob trusts Carol, Alice may transitively trust Carol.

Contrast with Hierarchical PKI which has a central root CA at the top.

SQL Acronym

What is the meaning of SQL in SQL injection?
❌ You answered: "Injecting SQL Commands in Input fields"
✅ Correct: Structured Query Language
The question asks for the acronym definition, not a description of the attack. SQL = Structured Query Language. It's the language used to communicate with relational databases.

Endpoint Hardening — Which Option

You are a contractor helping harden endpoints. Which could you implement?
❌ You may have selected only one option
✅ Correct: Install a HIPS, HIDS, and/or an EDR
The key word is "harden" endpoints. Hardening = strengthening security proactively.
✅ HIPS/HIDS/EDR = monitoring + prevention tools = endpoint hardening
⚠ "Disable ALL ports and protocols" = too extreme, breaks functionality
⚠ "Install antivirus" = good but AV alone isn't called "hardening"
⚠ "Use patch management" = good practice but not endpoint-specific hardening

OCSP Network Error

Browser shows "network error" when visiting a gaming site. What caused it?
❌ You may have selected certificate revocation
✅ Correct: OCSP was not able to access the server it was trying to contact.
A network error (not a security warning or revocation notice) means connectivity failed. OCSP needs to reach its responder server to check certificate status. If OCSP can't connect = network error.

If the cert was revoked = you'd get a security warning, not a generic network error.

Malware Definition (True/False)

True or False: Malware is a SOFTWARE-LIMITED attack designed to perform harmful actions.
❌ You answered: TRUE (HI)
✅ Correct: FALSE (LO)
Malware is described as "software designed to interfere with a computer's normal functions." The word "software-limited" is the trick — malware is not "limited" in scope; it can perform a wide variety of harmful actions. The statement is false because "software-limited" implies restriction, which is inaccurate.

OCSP Stapling (True/False)

True or False: OCSP stapling improves performance and reduces client requests.
❌ You answered: FALSE (LO)
✅ Correct: TRUE (HI)
OCSP Stapling = the web server periodically fetches a signed OCSP response from the CA and "staples" it to the TLS handshake. The client gets the status without making a separate request to the CA.

Result: ✅ faster handshakes, ✅ reduced CA server load, ✅ better privacy (client doesn't ping CA directly).

IoA vs IoC

Which statement about IoA is INCORRECT?
❌ You may have confused IoA with IoC
✅ Correct wrong answer: "An IoA is evidence an attack occurred." — that's actually an IoC
IoA (Indicator of Attack) = signs that an attack is currently happening or about to happen (real-time)
IoC (Indicator of Compromise) = evidence that an attack already occurred (forensic/post-incident)

"A user can't log in a day before their password expires" = normal event, NOT an IoA
"Email checked in Europe + file downloaded in Australia 6 min later" = impossible travel = ✅ IoA

Digital Certificate Contents

What type of information is found in a digital signature and/or digital certificate?
❌ Common wrong answer: digital signature contains public key
✅ Correct: A digital certificate CAN contain a postal address.
Digital Certificate contains: public key, identity info (name, org, email, address), validity dates, CA signature
Digital Signature = a hash of the message encrypted with the SENDER's private key. It does NOT contain a key itself.

❌ "Digital signature contains a public key" — FALSE (it's a hash/encrypted hash)
❌ "Digital certificate contains a private key" — NEVER. Private keys are never in certs.
✅ "Digital certificate can contain a postal address" — TRUE (Subject field can include address)

Web Application Vulnerability Target

A vulnerability in a web application infrastructure is most likely to affect which of the following?
❌ You may have selected OS or Network
✅ Correct: Platform
Web application infrastructure = the platform (web server, framework, runtime environment). A vulnerability here affects the platform layer — the environment on which the app runs (e.g., Apache, Node.js, IIS), not just the OS or network.
📌 Core Framework
Malware is classified by its primary action: Kidnap · Eavesdrop · Masquerade · Launch · Sidestep

🔒 KIDNAP — Ransomware

🔒 Blocking Ransomware
Manipulates the OS to block all normal access. You can't use the computer at all. Desktop is locked — like a fake government message popup demanding payment.
🔐 Locking Ransomware
Encrypts some or all files on the device so they can't be opened. Also targets all connected network drives, USB drives, NAS, cloud storage. This is why it's so serious.
⭐ Exam Trap: Ransomware Scope
Locking ransomware = encrypts files on the local device AND any network/storage connected to it. That's what makes it devastating — one infected USB can encrypt your entire company's shared drives.
🧠 Mnemonic — Ransomware Types
"BLOCK the door vs LOCK the files"
BLOCKing = blocks access to computer (can't use it) | LOCKing = locks (encrypts) your files

👂 EAVESDROP — Spyware & Keyloggers

⌨ Keylogger
Silently records every keystroke. Can be software (installed program) or hardware (physical USB device plugged between keyboard and PC). Captures passwords, credit cards, personal info.
👁 Spyware
Tracking software deployed without user consent or control. Monitors behavior, browsing, location. Not always obviously malicious — often bundled with free software.

🎭 MASQUERADE — Trojans

🐴 Computer Trojan
Appears to be a legitimate/benign program but performs malicious actions behind the scenes. Does NOT replicate itself (unlike viruses).
🖥 Remote Access Trojan (RAT)
Trojan + unauthorized remote access using specially configured communication protocols. Creates a backdoor giving the attacker unrestricted access to the victim's system.

🚀 LAUNCH — Viruses, Worms, Bots

Malware How it spreads Key characteristic Exam note

Fileless Virus No file attachment — loads into RAM Uses native OS processes; persistent, hard to detect ⭐ Quiz-worthy

"There is a virus that operates without appending itself to files." = TRUE — that's the fileless virus! It operates entirely in RAM.

🕵 SIDESTEP — Logic Bombs, Rootkits, Backdoors

💣 Logic Bomb
Code added to a legitimate program. Lies dormant until a specific logical event triggers it (date, action, login). Evades detection until triggered.
🌳 Rootkit
Hides its own presence AND other malware by accessing "lower layers" of the OS. Makes alterations so AV can't see it.
🚪 Backdoor
Provides access to a computer/program/service that circumvents normal security. Can be installed by an attacker or left by a developer intentionally.

📌 Key Concept
Application attacks target vulnerabilities in applications. They often result in privilege escalation — gaining more access than authorized.

Buffer Overflow & Memory Injection

💾 Buffer Overflow
A process stores data in RAM beyond the boundaries of a fixed-length buffer. Extra data overflows into adjacent memory.

Also called: memory injection (something injected into RAM).
Root cause: poor coding practices — improper input handling, not validating/filtering user input.
🏁 Race Condition
Occurs when two concurrent threads access a shared resource simultaneously. Can cause NULL pointer/object dereference → program crash or exploit. Root cause: poor coding.

Defending Against App Attacks

🧹 Filter Inputs (SQLi defense)
Validate and sanitize all user input before it reaches the database. Prevent SQL commands from being injected through form fields.
🍪 Secure Cookies
Cookies sent only over HTTPS (encrypted). Prevents interception by unauthorized parties during transmission. A web browser protection mechanism.
📋 HTTP Response Headers
Headers that instruct the browser how to behave with the website. Can prevent XSS, clickjacking, and other browser-level attacks.

⚠ Mobile Device Vulnerabilities

🔓 Physical Security
Mobile devices are frequently lost or stolen. Physical access = full access if no strong authentication. First line of defense = screen lock + strong passcode.
🔄 Limited Updates
Security patches distributed via OTA (Over-The-Air) firmware updates. Users often delay or skip updates. Unpatched devices = known vulnerabilities exploitable by attackers.
📍 Location Tracking
Devices using geolocation are at increased risk of targeted physical attacks. Related risk: GPS tagging — photos embed GPS coordinates in metadata, revealing user's location.
🎙 Unauthorized Recording
By infecting a device with malware, a threat actor can spy on the victim and record conversations or videos remotely — without the user knowing.

🔌 Connection Vulnerabilities ⭐

Name What it is The Vulnerability
Tethering Sharing a mobile device's internet connection with other devices via Bluetooth or Wi-Fi. An unsecured mobile device may infect other tethered devices or the corporate network.
USB OTG
On-The-Go		 OTG device can act as either a HOST (connects USB drives) or a PERIPHERAL (mass storage) to another host. Connecting a malicious flash drive could infect the device. Or, if used as peripheral connected to infected computer, malware is sent to the device.

📦 Accessing Untrusted Content ⭐ KCA 6-1

Jailbreaking = Apple iOS  |  Rooting = Android  |  Sideloading = downloading from unofficial 3rd-party app store

KCA 6-1 Answer: Employee trying to circumvent built-in limits on Android smartphone = A. Rooting
🍎 Jailbreaking (iOS)
Circumventing the built-in installation limitations on an Apple iOS device. Allows installing apps outside the App Store. Removes OS security restrictions.
🤖 Rooting (Android)
Circumventing the built-in installation limitations on an Android device. Grants root-level access. Enables sideloading from unofficial sources. ⭐ KCA 6-1 answer
📥 Sideloading
Downloading apps from an unofficial third-party app store (not the official App Store or Google Play). The act of installing an app this way — enabled by jailbreaking/rooting.
📱 SMS/MMS/RCS Attacks
Untrusted content can invade mobile devices through text messages (SMS, MMS, RCS). Malicious links or files in messages. Smishing = SMS phishing.
📷 QR Code Attacks
Attacker creates an advertisement listing a reputable website but includes a QR code with a malicious URL. Victim scans and is sent to attacker's site instead.

🛡 Protecting Mobile Devices

🔑 Strong Authentication
Verifying the authentic user involves strong passcode + screen lock. Options: passcode, PIN, fingerprint, facial recognition, or unlock pattern (connecting dots).
🗂 Segmentation / Containerization
Segmentation = separates business data from personal data. Containerization = storage split into business and personal "containers." Helps avoid data ownership privacy/legal issues.
🗑 Remote Wipe
If a lost or stolen device cannot be located, it may be necessary to perform a remote wipe — erase all data on the device remotely to prevent data breach.

🔧 Embedded Systems & Specialized Devices

📌 Definition
An embedded system = computer hardware and software contained within a larger system, designed for a specific function. Examples: car systems, medical devices, smart meters.
🍓 Raspberry Pi
One of the most common hardware components for embedded systems. A low-cost, credit-card-sized computer motherboard. Similar device: Arduino.
⚡ FPGA
Field-Programmable Gate Array — a hardware "chip" that can be programmed by the user to carry out one or more logical operations. Reprogrammable after manufacturing.
💾 SoC ⭐
System on a Chip — combines ALL required electronic circuits of various computer components on a single chip. SoCs often use an RTOS. Found in smartphones, IoT devices.
⏱ RTOS ⭐ KCA 6-2
Real-Time Operating System — a specifically designed OS for SoCs in embedded/specialized systems. Designed for deterministic, time-critical processing. KCA 6-2 Answer: B. RTOS
⭐ KCA 6-2 — Which OS is typically found on an embedded system? → RTOS
SoC (A) is the hardware chip, not the OS. OTG (C) is a USB connection type. COPE (D) is a mobile deployment model. Only RTOS (B) is an operating system.

🏭 Industrial Systems — ICS & SCADA

🏗 ICS — Industrial Control Systems
Collect, monitor, and process real-time data so machines can directly control devices (valves, pumps, motors) without human intervention.
📊 SCADA
Supervisory Control and Data Acquisition — manages ICSs. Helps maintain efficiency and provides information on issues to help reduce downtime. Manages critical infrastructure.

🔒 SCADA/ICS Hardening Steps

# Hardening Step
1 Clearly define security roles, responsibilities, and authorities for managers, admins, and users
2 Identify security requirements
3 Disconnect unnecessary connections to the SCADA network
4 Do NOT rely on proprietary protocols to protect the network
5 Test to identify and evaluate possible attack scenarios
6 Evaluate and strengthen the security of all connections to the SCADA network

🌐 IoT — Internet of Things

🌐 What is IoT?
Connecting any device to the Internet for the purpose of sending and receiving data. Examples: thermostats, coffee makers, tire sensors, washing machines, light bulbs, toothbrushes. Avg 22 connected devices per household (2022).
⚠ IoT Security Problem
SCADA, specialized systems, and IoT devices have low resilience to resist attacks. Key constraint: adding cryptography requires time + energy, which is scarce for small, low-power devices = resource vs security constraint.

⚖ IoT Legislation

🇺🇸 IoT Cybersecurity Improvement Act 2020
Federal law requiring agencies to increase cybersecurity for IoT devices owned/controlled by the federal government.
📋 California & Oregon State Laws (2020)
State laws requiring that connected devices be equipped with "reasonable security features". Went into effect 2020.
🏥 FDA Medical Device Powers (2022)
U.S. FDA gained new authority from legislators to set minimum security standards for medical-device manufacturers.

🔐 Application Security — Attacks & Defenses

Attack Type How it works Defense
Executable Files Attack Trick the vulnerable application into modifying or creating executable files on the system. Prevent the application from creating or modifying executable files during its normal function.
System Tampering Use the vulnerable app to modify sensitive OS areas (Windows registry, startup files) and exploit those modifications. Do not allow applications to modify special areas of the OS.

⚙ Application Development Models

💧 Waterfall Model
Uses a sequential design process. Each phase must complete before the next begins. Stages: Development → Testing → Staging → Production. Less flexible for changes.
🔄 Agile Model
Takes an incremental approach, allowing software issues to be incrementally discovered. Flexible and iterative — delivers working software in short cycles (sprints).
🛡 SecDevOps
Integrating secure development best practices into the agile model. Enables: Continuous monitoring, validation, integration, delivery, and deployment. Security built in from the start.

🧪 Code Testing — Static vs Dynamic ⭐ KCA 6-3

⭐ KCA 6-3 — Another name for runtime verification? → Dynamic Code Analysis (B)
Static = before compilation | Dynamic = after compilation (while running). Runtime = running = Dynamic.
📋 Static Code Analysis
Tests run before the source code is compiled. May be accompanied by manual peer reviews. Catches coding errors early without executing the program.
▶ Dynamic Code Analysis ⭐
Security testing performed after source code is compiled = also called runtime verification. All components are integrated and running. KCA 6-3 Answer: B. Dynamic code analysis
🎲 Fuzzing
Used by dynamic code analysis tools. Provides random input to a program in an attempt to trigger exceptions (memory corruption, crashes, security breaches). Stress-tests input handling.
🧠 Mnemonic — Static vs Dynamic Code Analysis
"Static = Source code · Dynamic = Running code"
Static = the code is static (not yet running) — tested before compilation
Dynamic = the code is in motion (executing) — tested after compilation while running = runtime verification
Fuzzing is a dynamic technique (throws random inputs at running program)

🎯 Module 6 Specific Exam Tips

  • M6-1 Android = Rooting. iOS = Jailbreaking. Never confuse these. The exam will give you the specific device (Android vs iPhone) and you must use the correct term. Sideloading is the action of downloading from an unofficial store — it's the RESULT of rooting/jailbreaking, not the process itself.
  • M6-2 RTOS is an OS type, SoC is hardware. When asked "what OS runs on an embedded system" — RTOS. When asked "what hardware integrates all components on one chip" — SoC. Don't confuse the hardware (SoC) with the software (RTOS).
  • M6-3 Runtime verification = Dynamic code analysis. "Runtime" = the code is running = DYNAMIC. Static = before compilation (code is not executing). Fuzzing is a dynamic technique specifically.
  • M6-4 For deployment models, focus on WHO OWNS and WHO PAYS. BYOD = employee owns. COPE = company pays, employee uses personally. CYOD = employee picks, business owns contract. Corporate Owned = company owns, work only. VDI = data lives on server, not device.
  • M6-5 Malicious USB cable = recognized as Human Interface Device. The key detail is WHY it's dangerous: the device thinks the cable is a keyboard or mouse, which grants the attacker HID-level permissions (input control).
  • M6-6 MDM/MAM/MCM/UEM hierarchy: MDM is most basic (device only). UEM is most comprehensive (device + apps + content). If an exam question asks "what manages apps and controls which apps can be installed" = MAM. "What manages ALL aspects" = UEM.

🎯 Module 5 Exam Techniques (Carry-Over)

  • 01 Watch for "technical term" traps. The exam uses exact terminology. "Duration" ≠ Cryptoperiod. "Certificate of Trust" ≠ Web of Trust. When in doubt, go with the most technical-sounding specific term.
  • 02 For True/False questions, watch for absolutes. Words like "only," "always," "never," "limited" are often signals that the statement is FALSE. "Software-limited" malware = false. "Repository stores revoked certs ONLY" = false.
  • 03 CSRF vs SSRF: remember the target. C = Client/user is the target. S = Server is the target. This exact comparison appeared in your quiz.
  • 04 For scenario questions, focus on keywords: "temporary" / "extended leave" → suspend. "Compromised" / "terminated" → revoke. "Performance" + "certificate" → OCSP Stapling.
  • 05 Error types matter. Network error = OCSP can't reach server. Security warning = certificate revoked. Generic popup demanding payment = blocking ransomware (extortion). Know what each condition points to.
  • 06 For "who does X on behalf of Y" questions: RA acts on behalf of CA. Intermediate CA does NOT act "on behalf of" — it issues its own certs.
